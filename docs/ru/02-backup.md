Результат: каждую ночь на сервере появляется зашифрованный снимок, а вы
проверили, что он открывается вашим ключом. Предполагается, что holdfast уже
установлен ([01-install.md](01-install.md)).

Порядок: ключ → публичный ключ в конфигурации → `--dry-run` → первый бэкап →
проверка → расписание → (по желанию) вторая копия.

## 1. Ключ шифрования

**Главное правило: приватный ключ не должен лежать на сервере, чьи копии он
открывает.** holdfast шифрует публичным ключом; серверу нужна только публичная
часть. Поэтому ключ создаётся у вас.

**У себя, Linux или WSL:**

```sh
age-keygen -o ~/holdfast-age-key.txt
```

**У себя, Windows без `age`** — одноразовым контейнером (Docker Desktop), из
Git Bash:

```sh
docker run --rm alpine:3.20 sh -c 'apk add -q age && age-keygen' > holdfast-age-key.txt
```

> В PowerShell 5.1 `>` пишет файл в другой кодировке, и `age` его не прочитает.
> Используйте Git Bash или замените `> holdfast-age-key.txt` на
> `| Out-File -Encoding ascii holdfast-age-key.txt`.

В файле три строки: дата, публичный ключ (`# public key: age1...`) и приватный
(`AGE-SECRET-KEY-1...`). Публичный ключ можно получить из файла в любой момент:

```sh
age-keygen -y holdfast-age-key.txt
```

Что делать с файлом:

- хранить **минимум в двух местах** (менеджер паролей и носитель отдельно от
  сервера);
- не класть на защищаемый сервер и не держать единственную копию на ноутбуке,
  с которого вы им управляете;
- по желанию — второй, запасной ключ на другом носителе (см. шаг 2).

Если ключ уже создан на сервере: заберите его (`scp`), сверьте `sha256sum` на
обеих сторонах, затем сотрите на сервере `shred -u /путь/key.txt`.

## 2. Публичный ключ в конфигурации

**На сервере** откройте `/etc/holdfast/holdfast.toml` (`nano`). В нём уже есть
раздел `[encryption]` — поправьте его, второй не добавляйте:

```toml
[encryption]
recipients = ["age1ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ"]
```

Основной и запасной — списком: `recipients = ["age1основной...", "age1запасной..."]`.
Расшифровать архив сможет любой из них.

Без ключа бэкап остановится до первого байта:
`encryption is on and no recipient is configured`. Это защита:
незашифрованный архив holdfast не напишет.

## 3. Посмотреть, что будет взято

**На сервере:**

```sh
holdfast backup --dry-run
```

Ничего не пишет и не меняет, код возврата 0. Делает тот же выбор, что и
настоящий бэкап, и печатает его. Подробно, как читать вывод и что делать со
строками `not taken:`, — в [03-contents.md](03-contents.md). Здесь достаточно
проверить:

- в списке есть всё, что вам дорого: база, папка проекта, файлы сайта;
- нет строки `the backup would refuse:` в разделе `warnings:` — она значит, что
  настоящий бэкап не запустится (нет `bash`/`age`, мало места на диске).

Что `--dry-run` проверяет по-настоящему: конфигурацию, ответ Docker, пароль к
каждой базе (он спрашивает у сервера список баз). Чего не делает: не снимает
дампы и не читает файлы, поэтому ошибка чтения данных всплывёт только в бэкапе.

## 4. Первый бэкап

**На сервере:**

```sh
holdfast backup
```

Печатается строка со снимком и список не взятого:

```
/opt/backups/20260923-021500 (31616210 bytes in 3 artifacts)
skipped volume a1a1a1…: no container uses it
```

Код возврата 0. Работа идёт во временной папке `.ДАТА.tmp` и переименовывается
в конце, поэтому оборванный запуск не оставляет ничего, что можно принять за
копию. Если любой компонент не отработал, не будет снимка вообще: «зелёная ночь
без дампа базы» намеренно невозможна.

Что в снимке (без ключа, прямо на сервере):

```sh
holdfast restore list --snapshot /opt/backups/latest
ls -lh /opt/backups/latest/
```

В снимке лежат зашифрованные артефакты (`*.age`), `manifest.json` (открытым
текстом: описывает снимок и нужен при восстановлении) и `SHA256SUMS`. Журнал
запусков — `/var/lib/holdfast/jobs/backup.json`.

## 5. Проверить копию (обязательно)

Ключа на сервере нет, поэтому проверка делается у вас или на другой машине с
ключом. Полная процедура — в [04-restore.md](04-restore.md#проверка-копии-без-риска).

## 6. Расписание

Своего планировщика у holdfast нет. **На сервере** создайте `/etc/cron.d/holdfast`:

```
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin

30 2 * * * root /usr/local/bin/holdfast backup
0  7 * * * root /usr/local/bin/holdfast audit > /dev/null
```

В конце файла должна быть пустая строка. Затем:

```sh
chmod 644 /etc/cron.d/holdfast
systemctl is-active cron      # active
```

Коды возврата, на которые смотрит монитор:

| Команда | 0 | 1 |
|---|---|---|
| `holdfast backup` | снимок снят, либо другой бэкап уже идёт | бэкап не удался |
| `holdfast audit` | ни одна проверка не провалена | есть FAIL |
| `holdfast restore verify` | все артефакты читаются | хоть один не прочитался |

Оповещений holdfast пока не умеет: ненулевой код должен заметить тот, кто
запускает команду.

## 7. Хранение и свободное место

Настройки в разделе `[backup]` файла `/etc/holdfast/holdfast.toml`:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `root` | `/opt/backups` | куда класть снимки |
| `retention_days` | `7` | снимки старше этого числа дней удаляются; `0` — не удалять. Самый новый снимок не удаляется никогда |
| `min_free_gb` | `8` | не запускать бэкап, если после него останется меньше |
| `zstd_level` | `10` | степень сжатия |

Ротация идёт только после успешного бэкапа.

## 8. Вторая копия (рекомендуется)

Снимок, лежащий только на самом сервере, пропадает вместе с ним.

**На сервере:**

```sh
apt-get install -y rclone
rclone config          # диалог: имя хранилища, тип, доступы
```

В `/etc/holdfast/holdfast.toml`, в уже существующем разделе `[offsite]`:

```toml
[offsite]
remote = "shared:backups"
timeout_minutes = 120
```

Копия уходит после готовности снимка и ложится в папку с именем машины:
`shared:backups/web-1/20260923-021500/`. holdfast проверяет, что файлы
долетели, и **ничего не удаляет на удалённой стороне** (старые снимки там
чистите сами). Неудачная отправка не портит бэкап: сторож напоминает о ней
каждый день.

Чтобы вернуть снимок с удалённого хранилища, используйте `rclone` напрямую,
см. [04-restore.md](04-restore.md#б-новый-сервер-с-нуля).

## 9. Первый аудит (по желанию)

```sh
holdfast audit
holdfast audit --baseline
```

На свежем сервере будет много FAIL — это честно (вход root по паролю,
отсутствие fail2ban, неограниченные журналы, непоставленные обновления).
`--baseline` печатает блок TOML с тем, что на машине сейчас считается нормой
(порты, соединения, адреса входов); лишнее вычеркните, остальное вставьте в
`holdfast.toml`. Сам аудит ничего не меняет. Список проверок: `docs/checks.md`.
