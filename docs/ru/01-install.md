Результат: на сервере работает команда `holdfast`, есть конфигурация машины, и
`holdfast config check` отвечает `configuration is complete`. Бэкап на этом
шаге ещё не настроен — он в [02-backup.md](02-backup.md).

Всё делается от `root`. Это же нужно и на **голом сервере** при восстановлении:
для него достаточно шагов 1–4 ниже, дальше — [04-restore.md](04-restore.md).

## Шаг 1. Вход на сервер

**У себя:**

```sh
ssh root@ВАШ_СЕРВЕР
```

Если SSH предупреждает, что ключ хоста изменился, не обходите предупреждение.
Ключ меняется, если сервер переустановили, провайдер отдал адрес другой машине
или соединение перехватывают. Первые два случая вы знаете за собой; иначе
сверьте отпечаток в панели провайдера и только потом уберите старую запись:

```sh
ssh-keygen -R ВАШ_СЕРВЕР
```

## Шаг 2. Системные пакеты

**На сервере:**

```sh
apt-get update && apt-get -y upgrade
apt-get install -y python3 python3-venv zstd age
```

Если приложение работает в контейнерах, нужен ещё Docker (на голом сервере
при восстановлении он тоже нужен):

```sh
sh <(curl -sSL https://get.docker.com)
```

> Строка выше использует синтаксис `bash` (`<(...)`). На сервере по умолчанию
> `bash`, так что работает; если у вас `sh` (dash), выполните `bash` и повторите.

| Программа | Зачем | Обязательна |
|---|---|---|
| `python3` 3.11+ и `python3-venv` | сам holdfast; сторонних библиотек не требует | да |
| `bash` | конвейеры идут через него (`sh` в Ubuntu — `dash`, он не заметил бы упавшую середину конвейера) | да, уже стоит |
| `tar` | архивы папок и томов | да, уже стоит |
| `zstd` | сжатие | да |
| `age` | шифрование; вместо него можно `gpg` | да, одно из двух |
| `docker` | только если данные в контейнерах | по ситуации |
| `rclone` | только для второй копии на удалённом хранилище | по ситуации |
| клиенты БД (`mysqldump`, `pg_dump` …) | только для баз **вне** контейнеров | по ситуации |

Проверка:

```sh
for t in python3 bash tar zstd age docker; do
  printf '%-8s %s\n' "$t" "$(command -v $t || echo ОТСУТСТВУЕТ)"
done
```

Слова `ОТСУТСТВУЕТ` быть не должно (для `docker` — если приложение в
контейнерах).

## Шаг 3. Установка holdfast

Отдельное окружение, чтобы не трогать системный Python. **На сервере:**

```sh
cd /root
git clone https://github.com/viktorplus/holdfast.git
python3 -m venv /opt/holdfast
/opt/holdfast/bin/pip install ./holdfast
ln -s /opt/holdfast/bin/holdfast /usr/local/bin/holdfast
holdfast version
```

Последняя команда должна напечатать `0.3.0`.

### Обновление позже

```sh
cd /root
git -C holdfast pull
/opt/holdfast/bin/pip install ./holdfast
holdfast version
```

Конфигурация и снимки лежат вне `/opt/holdfast`, обновление их не трогает.
Обновляетесь с 0.2 — см. [07-upgrade-from-0.2.md](07-upgrade-from-0.2.md).

## Шаг 4. Конфигурация машины

**На сервере:**

```sh
holdfast init --fresh --host-label web-1 --backup-mode auto
holdfast config check
```

Первая команда печатает `wrote /etc/holdfast/holdfast.toml`, вторая —
`configuration is complete`.

| Флаг | Что делает |
|---|---|
| `--fresh` | отдельная машина, ничего ни с кем не делит |
| `--host-label web-1` | имя, которым машина подписывается. **Запишите его.** Под ним лежат копии в удалённом хранилище, и именно его сверяет восстановление. Без флага берётся имя хоста |
| `--backup-mode auto` | holdfast сам смотрит в Docker и решает, что брать (по умолчанию). `manual` — только по списку, см. [03-contents.md](03-contents.md#режим-manual) |

`init` создаёт `/etc/holdfast/holdfast.toml` с правами `0600` и не
перезаписывает существующий файл. На машине **без Docker** ставьте
`--backup-mode manual`: в режиме `auto` бэкап без Docker остановится.

> `config check` смотрит только на настройки установки. Ключа шифрования и
> состава копии она не проверяет, поэтому «всё готово» ещё не значит, что бэкап
> запустится. Готовность бэкапа показывает `holdfast backup --dry-run`
> ([02-backup.md](02-backup.md)).

## Что где лежит после установки

```
/etc/holdfast/holdfast.toml          конфигурация машины, права 0600
/etc/holdfast/components.toml        только в режиме manual: список от --discover
/opt/holdfast/                       сама программа
/opt/backups/<дата-время>/           снимки
/opt/backups/latest                  ссылка на последний
/var/lib/holdfast/jobs/*.json        журнал: последний запуск и последний успех
/var/lib/holdfast/audit/last.json    последний отчёт сторожа
/etc/cron.d/holdfast                 расписание
```

Пути меняются ключами `backup.root`, `jobs.dir`, `audit.state_dir`,
`backup.lock_file`. Если вы поменяли `backup.root`, то снимки лежат там, а не в
`/opt/backups`.
